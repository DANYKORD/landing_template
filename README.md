# 🚀 Шаблон лендінгу — інструкція для власника сайту

Це шаблон для односторінкових сайтів-продажників. **Програмувати не потрібно.**
Щоб зробити новий сайт, достатньо:

1. покласти фото в папку `content/photos`
2. змінити тексти й ціну в файлі `content/texts.js`
3. вставити ключі у файл `content/keys.js`
4. виконати одну команду `npm run deploy`

> Усе, що вам потрібно змінювати, лежить у папці **`content`**. Інші папки чіпати не треба.

```
content/
├── photos/            ← ФОТО сайту
├── texts.js           ← ТЕКСТИ, ЦІНА, ТАЙМЕР
├── keys.js            ← ВАШІ КЛЮЧІ (не потрапляє на GitHub)
└── keys.example.js    ← зразок для keys.js
```

---

## 📸 Крок 1. Фото

Покладіть фото в папку `content/photos`. Сайт сам знайде їх **за назвою файлу** і поставить у потрібне місце.
Розширення може бути будь-яким: `.jpg`, `.png`, `.webp`, `.gif`.

| Назва файлу   | Де з'являється на сайті (згори донизу)  |
|---------------|-----------------------------------------|
| `main`        | Головне фото на самому верху            |
| `1`           | Блок опису №1                           |
| `2`           | Блок опису №2                           |
| `3`           | Блок опису №3                           |
| `1_comment`   | Відгук №1 (у гортальці відгуків)        |
| `2_comment`   | Відгук №2                               |
| `3_comment`   | Відгук №3                               |
| `footer`      | Картинка в самому низу (оплата/доставка)|

**Корисно знати:**
- Щоб **замінити** фото — просто покладіть новий файл з тією ж назвою (старий видаліть).
- Потрібно **більше блоків чи відгуків**? Додайте `4`, `5` … або `4_comment`, `5_comment` … — вони з'являться самі.
- Якщо якогось фото немає — цей елемент просто не показується, сайт не зламається.
- В одній папці не повинно бути двох файлів з однаковою назвою (наприклад `main.jpg` і `main.png`).
- ⚠ У Windows часто приховані розширення. Якщо файл названо `main.jpg`, а розширення приховане, ви бачите просто `main` — це правильно. Не перейменовуйте в `main.jpg` вручну, інакше вийде `main.jpg.jpg`.

> 💡 **Вага фото = швидкість сайту і менше витрат на Firebase.**
> Сайт має ширину до 480 px, тому фото шириною **~1000 px** більш ніж достатньо.
> Перед завантаженням стисніть фото, наприклад програмою [Batch Picture Resize](https://www.rw-designer.com/picture-resize).
> Орієнтир: кожне фото — до **300 КБ**. GIF-анімації дуже важкі (бувають по 30 МБ) — краще замінити їх фото.

## ✏️ Крок 2. Тексти, ціна, таймер

Відкрийте файл `content/texts.js` будь-яким текстовим редактором (Блокнот, Notepad++, VS Code).

Правила прості:
- Змінюйте **тільки текст між знаками** `` ` ` ``
- Усередині тексту можна натискати **Enter** — на сайті буде новий рядок.
- **Ціни** пишіть просто цифрами: `price: 350,`
- **Не видаляйте** коми в кінці рядків, двокрапки та дужки `{ } [ ]`.

Приклад:
```js
productTitle: `Засіб для відновлення кольору дерева`,
price: 350,
oldPrice: 700,
```

**Таймер акції** — вкажіть дату закінчення у форматі `рік-місяць-день година:хвилина`:
```js
endDate: `2026-12-31 23:59`,
```
Щоб сховати таймер — замініть `show: true` на `show: false`.

## 🔑 Крок 3. Ключі

1. У папці `content` скопіюйте файл `keys.example.js` і назвіть копію **`keys.js`**.
2. Заповніть три значення:

| Поле               | Що це                                                                 |
|--------------------|-----------------------------------------------------------------------|
| `googleSheetsUrl`  | Посилання на Google Apps Script — сюди приходять замовлення          |
| `novaPoshtaApiKey` | Ключ API Нової Пошти — для підказок міст і відділень                 |
| `firebaseProjectId`| ID проекту Firebase — куди публікувати сайт                          |

> 🔒 Файл `keys.js` не завантажується на GitHub — ваші ключі залишаються тільки на вашому комп'ютері.

## 👀 Подивитися сайт перед публікацією

Відкрийте папку проекту, клацніть в адресному рядку Провідника, введіть `cmd` і натисніть Enter — відкриється термінал у цій папці.

**Перший раз** (встановлення, ~1 хв):
```bash
npm install
```

**Запустити сайт у себе:**
```bash
npm run dev
```
Відкрийте в браузері адресу, яку покаже термінал (зазвичай http://localhost:5173).
Тепер кожна зміна фото чи тексту одразу видна в браузері після збереження файлу.
Зупинити — `Ctrl + C` у терміналі.

## 🔥 Публікація на Firebase

### Один раз на комп'ютері

1. Встановіть **Node.js** (версія LTS) з сайту https://nodejs.org
2. Встановіть інструмент Firebase:
   ```bash
   npm install -g firebase-tools
   ```
3. Увійдіть у свій Google-акаунт:
   ```bash
   firebase login
   ```

### Один раз для кожного нового сайту

1. Зайдіть на https://console.firebase.google.com → **Add project / Створити проект**.
2. У проекті відкрийте **Hosting** → **Get started** (кроки в майстрі можна просто прогортати).
3. Скопіюйте **ID проекту** (видно в налаштуваннях проекту ⚙ → *Project settings* → *Project ID*, наприклад `domivka-shop`).
4. Вставте його в `content/keys.js` → `firebaseProjectId`.

### Опублікувати (кожного разу після змін)

```bash
npm run deploy
```

Ця команда сама збере сайт і завантажить його. Наприкінці з'явиться посилання на ваш сайт (`https://ID-проекту.web.app`).

> ✅ **Кожна публікація повністю замінює попередній сайт.** Видаляти старий вручну перед публікацією не потрібно — на сайті буде рівно те, що зараз у папці `content`.

## 🗑 Як прибрати те, що вже є на Firebase

**Вимкнути сайт повністю** (за адресою буде сторінка «Site Not Found»):
```bash
npm run site:off
```
Щоб увімкнути знову — просто `npm run deploy`.

**Звільнити місце (Storage) від старих версій.**
Firebase зберігає всі попередні публікації, щоб можна було відкотитися назад — через це росте «Storage».
Окремої команди для їх видалення у Firebase немає, тому це робиться в браузері:
1. https://console.firebase.google.com → ваш проект → **Hosting**.
2. Таблиця **Release history** → навпроти старих версій натисніть **⋮** → **Delete**.
   (Поточну, «живу» версію видалити не можна — і не треба.)
3. Щоб старі версії видалялися автоматично: у тій же таблиці **⋮** → **Release storage settings** → вкажіть, скільки версій зберігати (наприклад, `2`).

## 🆕 Як зробити новий сайт із цього шаблону

1. Скопіюйте всю папку проекту **без** папок `node_modules` і `dist`.
2. Замініть фото в `content/photos`.
3. Змініть тексти в `content/texts.js`.
4. У `content/keys.js` вкажіть новий `firebaseProjectId` (і, якщо потрібно, нову Google-таблицю).
5. У новій папці: `npm install`, потім `npm run deploy`.

## ❓ Якщо щось не працює

| Проблема | Що робити |
|----------|-----------|
| Після зміни `texts.js` сайт не відкривається / червона помилка | Найчастіше — пропущена кома або знак `` ` ``. Помилка в терміналі показує номер рядка — перевірте його. |
| Фото не з'явилось | Перевірте назву файлу (точно `main`, `1`, `1_comment` …) і що він лежить саме в `content/photos`. |
| Замовлення не приходять у таблицю | Перевірте `googleSheetsUrl` у `content/keys.js`. |
| Не підказує міста Нової Пошти | Перевірте `novaPoshtaApiKey` у `content/keys.js`. |
| `firebase` не є командою | Виконайте `npm install -g firebase-tools`, потім закрийте і знову відкрийте термінал. |
| Помилка доступу при `npm run deploy` | Виконайте `firebase login` і перевірте `firebaseProjectId`. |

## 🛠 Для розробника

- Стек: React + Vite + Tailwind CSS.
- `src/config.js` збирає дані з `content/` під час збірки: фото знаходяться через `import.meta.glob` за назвою файлу, тексти — з `content/texts.js`, ключі — з `content/keys.js` (запасний варіант — `keys.example.js`).
- Слоти для фото підтримують і відео `.mp4` / `.webm` (автовідтворення без звуку) — легка заміна важким GIF.
- `npm run build` — збірка в `dist/`; `npm run deploy` / `npm run site:off` — див. `scripts/deploy.js`.
